Deploy dmama_api ด้วย NSSM

เป้าหมาย: ให้ Go API รันเป็น Windows Service, start หลัง reboot, มี log, health check และ rollback ได้

จุดสำคัญที่สุด: ตั้ง AppDirectory=C:\Services\dmama_api เพราะแอปอ่าน .env และเสิร์ฟไฟล์จาก template\ โดยอิง working directory

1. สร้าง release package

ใช้ source จาก commit/tag ที่ต้องการ deploy และควรให้ git status --porcelain ว่างก่อน build. โปรเจกต์กำหนด Go 1.25 ใน go.mod.

go version
go test ./...
$env:CGO_ENABLED = '0'
$env:GOOS = 'windows'
$env:GOARCH = 'amd64'
New-Item -ItemType Directory -Force .\dist | Out-Null
go build -trimpath -ldflags="-s -w" -o .\dist\dmama_api.exe .\cmd\server

นำไฟล์ต่อไปนี้ไป server: dmama_api.exe, template\, migrations\ และสร้าง .env จาก .env.example. ไม่ต้องนำ Go source ไป production ถ้าไม่ต้อง build บน server.

2. จัดโฟลเดอร์บน server

C:\Services\dmama_api\
  dmama_api.exe
  .env
  template\
  migrations\
  logs\

ค่าที่ต้องตรวจใน .env:

ตัวแปรความหมาย
DATABASE_URLจำเป็น — PostgreSQL หลัก; ว่างหรือเชื่อมไม่ได้ทำให้ service ออกทันที
GISDATA_URLPostgreSQL 16 สำหรับ feature topology และ usage log; ว่างแล้ว API หลักยังรัน แต่ feature/usage ถูกปิด
MONGO_URIVallaris/MongoDB; ว่างแล้ว feature CRUD ถูกปิด
PORTค่าเริ่มต้น 5013
DMAMA_KEYAPI key production; endpoint health ไม่ต้องใช้ key

3. เตรียม database

ให้ DBA รัน migrations\0001_dmama_layer.sql และ 0002_auth_logs_dmama_use.sql กับฐานที่ระบุใน GISDATA_URL พร้อม ON_ERROR_STOP. App role ต้องมีสิทธิ์ใช้งาน schema/table ที่ migration สร้าง.

4. ติดตั้ง NSSM service

ดาวน์โหลด NSSM x64 จากแหล่งทางการ วางใน path คงที่ และอย่าย้าย nssm.exe หลัง install. เปิด PowerShell แบบ Administrator:

$Service = 'dmama_api'
$Root    = 'C:\Services\dmama_api'
$Nssm    = 'C:\nssm-2.24\nssm-2.24\win64\nssm.exe'
$Exe     = Join-Path $Root 'dmama_api.exe'
$Log     = Join-Path $Root 'logs\service.log'

New-Item -ItemType Directory -Force (Join-Path $Root 'logs') | Out-Null
& $Nssm install $Service $Exe
& $Nssm set $Service AppDirectory $Root
& $Nssm set $Service DisplayName 'DMAMA API'
& $Nssm set $Service Description 'DMAMA Fiber API'
& $Nssm set $Service Start SERVICE_DELAYED_AUTO_START
& $Nssm set $Service AppStdout $Log
& $Nssm set $Service AppStderr $Log
& $Nssm set $Service AppStdoutCreationDisposition 4
& $Nssm set $Service AppStderrCreationDisposition 4
& $Nssm set $Service AppRotateFiles 1
& $Nssm set $Service AppRotateOnline 0
& $Nssm set $Service AppRotateBytes 10485760
& $Nssm set $Service AppRestartDelay 5000

5. ใช้ service identity ที่จำกัดสิทธิ์

สำหรับ server เดี่ยว ใช้ virtual account ที่ Windows จัดการ password ให้:

& $Nssm set $Service ObjectName "NT SERVICE\$Service"
icacls $Root /grant "NT SERVICE\${Service}:(OI)(CI)RX"
icacls (Join-Path $Root 'logs') /grant "NT SERVICE\${Service}:(OI)(CI)M"

ถ้าต้อง authenticate ไป network resource ด้วย domain identity ให้ใช้ gMSA/domain service account ตามนโยบายองค์กรแทน. จำกัดสิทธิ์อ่าน .env ให้ Administrators, SYSTEM และ service identity เท่านั้น.

6. Start และตรวจรับ

& $Nssm start $Service
Get-Service $Service
Invoke-RestMethod 'http://127.0.0.1:5013/api/health'
Get-Content $Log -Tail 100
ผล health ที่ถูกต้องคือ response success และ data.status = "ok". จากนั้นตรวจ /api/monitor/readiness พร้อม X-API-Key เพื่อดู PostgreSQL 16, MongoDB และ dmama_layer.

7. Firewall / reverse proxy

แนะนำให้ nginx/IIS อยู่เครื่องเดียวกันและเรียก 127.0.0.1:5013 โดยไม่เปิด port 5013 ออก network. หากจำเป็นต้องเข้าตรง ให้จำกัด source subnet:

New-NetFirewallRule -DisplayName 'DMAMA API 5013' -Direction Inbound `
  -Action Allow -Protocol TCP -LocalPort 5013 -RemoteAddress '10.250.0.0/16'

8. อัปเดตและ rollback

& $Nssm stop $Service
Copy-Item $Exe "$Exe.bak" -Force
Copy-Item 'C:\Staging\dmama_api.exe' $Exe -Force
& $Nssm start $Service
Invoke-RestMethod 'http://127.0.0.1:5013/api/health'

ถ้า health ไม่ผ่าน: stop, นำ .bak กลับ, start และอ่าน log. การเปลี่ยน schema ต้องมีแผน rollback แยกจาก binary.

แบบฝึกตรวจรับ

  1. หยุด service แล้ว start ใหม่ จากนั้น health ต้องกลับมา.
  2. reboot server ใน maintenance window แล้ว service ต้องเป็น Running.
  3. เปลี่ยน URL ฐานทดสอบให้ผิดชั่วคราวใน non-production และอ่านสาเหตุจาก log.
  4. ซ้อม rollback binary หนึ่งครั้งก่อน production cutover.
