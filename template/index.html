DMAMA API Documentation

REST API สำหรับระบบ DMAMA พัฒนาจาก Go + Fiber + pgx เชื่อมต่อ PostgreSQL 9.4 + PostGIS รองรับการค้นหาเชิงพื้นที่สำหรับชั้นข้อมูล เส้นท่อ มาตรวัดน้ำ ประตูน้ำ จุดซ่อมท่อ ขอบเขต DMA และสำนักงานประปา

การยืนยันตัวตน (Authentication)

ทุก endpoint (ยกเว้น /api/health) ต้องแนบ API key ผ่าน header X-API-Key

Request Header 
X-API-Key: your_api_key_here

ตัวอย่างการใช้งาน

cURL 
curl -H "X-API-Key: your_api_key_here" \
  "http://localhost:5013/api/pipe/assign-logger" \
  -X POST -H "Content-Type: application/json" \
  -d '{"lat":13.7,"lng":100.5,"region":1}'
JavaScript (fetch) 
const res = await fetch('/api/pipe/assign-logger', {
  method: 'POST',
  headers: {
    'X-API-Key': 'your_api_key_here',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({ lat: 13.7, lng: 100.5, region: 1 })
})
const data = await res.json()
Python (requests) 
import requests

headers = {'X-API-Key': 'your_api_key_here'}
res = requests.get(
    'http://localhost:5013/api/pipe/geometry',
    headers=headers,
    params={'region': 1, 'pipe_id': 'PIPE001'}
)

หมายเหตุ: ถ้า DMAMA_KEY ไม่ได้ตั้งค่าในไฟล์ .env การยืนยันตัวตนจะถูกปิด (dev mode)

X-User-Id: สำหรับ endpoint ที่เขียนข้อมูล (Feature CRUD) แนบ header X-User-Id เช่น 10090 ระบบจะค้น claystone.users ด้วย 10090@pwa.co.th เพื่อบันทึก _createdBy/_updatedBy

Usage logging: ทุก request ภายใต้ /api (ยกเว้น /health) จะถูกบันทึกปริมาณข้อมูล (KB/MB/GB), ระยะเวลา และช่วงเวลาลง auth_logs.dmama_use โดยอ้างอิงจาก API key ที่เรียก

รูปแบบ Response

ทุก endpoint ส่งคืนข้อมูลในรูปแบบ JSON เดียวกัน:

JSON Response 
{
  "success": true,
  "data": { ... },
  "error": null,
  "count": 10
}
Field Type คำอธิบาย
successbooleanสถานะความสำเร็จของ request
dataanyข้อมูลที่ส่งคืน (null ถ้าไม่พบ)
errorstringข้อความข้อผิดพลาด (เฉพาะเมื่อ success=false)
countintจำนวนรายการ (เฉพาะ endpoint ที่คืนค่าเป็น list)

Playground / Test Case

อ้างอิงจากไฟล์ note/dmama_api.postman_collection.json สำหรับ import เข้า Postman และทำ smoke test ให้ตรงกับ endpoint ปัจจุบัน

Suggested test flow

  1. Import Postman collection and set X-API-Key
  2. Verify /api/health before testing protected routes
  3. Test one endpoint from each group: Pipe, DMA, Office/Waterworks, Asset
  4. Compare format=geojson and format=wkt on geometry endpoints
  5. For /api/asset/in-area, test both Polygon and LineString + buffer

Current collection highlights

  • Pipe: assign-logger, geometry, at-leakpoint, assets
  • DMA: boundary, usage, daily_metercount, pipe-length-clipped
  • Shared data: office, waterworks
  • Spatial tools: asset/nearest, asset/in-area

GET /api/dma/stats
ใช้สำหรับดึงสถิติการใช้น้ำและจำนวนผู้ใช้น้ำรายเดือนใน DMA โดยแนะนำให้ส่ง year + month. ยังรองรับ column เพื่อ backward compatibility เช่น prswtusg, lstwtusg1..12.

คืนข้อมูลเป็น JSON แบบ nested แยกเป็น usage และ population พร้อมระบุ pwa_code, dma_id, และ column ที่ใช้ query.

Parameters

NameTypeRequiredคำอธิบาย

dma_idstringrequiredรหัส DMA เช่น 1

monthintpreferredเดือนข้อมูลที่ต้องการ 1..12
columnstringoptionalรองรับ backward compatibility เช่น prswtusg, lstwtusg1..12
regionintoptionalเขต 1..10; ถ้าไม่ส่งจะ resolve จาก pwa_code
Rules
  • ถ้าส่ง year/month ให้ใช้ year/month เป็นหลัก แม้จะส่ง column มาด้วย
  • ถ้าไม่ส่ง year/month ให้ใช้ column
  • ถ้าไม่ส่ง column ให้ default เป็น prswtusg
  • validate column ด้วย allowlist เท่านั้น ห้ามนำ input ไปต่อ SQL โดยตรง

Feature CRUD

Feature CRUD ใช้จัดการข้อมูลที่วาดจากระบบ DMAMA/Vallaris สำหรับ dma_boundary, flow_meter, และ step_test. MongoDB เป็น source of truth ส่วน PostGIS schema dmama_layer.<shape> เป็น mirror สำหรับตรวจ topology และค้นเชิงพื้นที่

shapegeometryกฎ topology
dma_boundaryPolygongeometry ต้อง valid และห้าม overlap กับ dma_boundary อื่นในสาขาเดียวกัน; dma_id ใช้เฉพาะ shape นี้
flow_meterPointต้องอยู่ใน coverage ของ dma_boundary ของสาขานั้น
step_testPolygonต้องเป็น polygon ที่ valid และอยู่ใน coverage ของ dma_boundary ของสาขานั้น

Request Body ที่ใช้ร่วมกัน

  • geometry: GeoJSON geometry ตามชนิดของ :shape และใช้พิกัด [lng, lat] (EPSG:4326)
  • properties: metadata ของ feature ส่งได้ตาม field งาน เช่น dmaNo, stepNo, remark
  • dma_id: ส่งเฉพาะ dma_boundary; ค่า 0 หรือไม่ส่ง หมายถึงให้ backend กำหนด max+1

หมายเหตุ: ค่า :pwaCode ใน URL เป็นสาขาหลักที่ใช้เลือก collection. Server จะตั้ง field ระบบให้เอง เช่น _id, pwaCode, _createdAt, _createdBy, _updatedAt, _updatedBy. สำหรับ endpoint ที่เขียนข้อมูลให้ส่ง X-User-Id เช่น 10090 เพื่อ map เป็น user ใน claystone.users

POST /api/features/:shape/:pwaCode/validate

ตรวจ topology แบบ dry-run โดยไม่บันทึก Mongo และไม่ upsert mirror. ถ้า body อ่านได้และ backend พร้อม แม้ geometry ไม่ผ่านกฎก็คืน 200 พร้อม valid:false; error จาก body/database จะคืน error ตามปกติ

Request Body (flow_meter)

JSON
{
  "geometry": { "type": "Point", "coordinates": [99.000763952422, 18.79578125261918] },
  "properties": { "remark": "postman validate" }
}

Response

JSON
{
  "success": true,
  "data": {
    "valid": false,
    "violations": ["point is outside the branch dma_boundary coverage"],
    "warnings": []
  }
}
POST /api/features/:shape/:pwaCode

สร้าง feature ใหม่: validate topology ก่อน จากนั้น insert ลง MongoDB และ upsert เข้า PostGIS mirror. สำเร็จคืน 201; ถ้า topology ไม่ผ่านคืน 400 พร้อมรายการ violations

GET /api/features/:shape/:pwaCode

ดึง feature ทั้งหมดของสาขาและชนิดนั้นจาก MongoDB. ใส่ query bbox=minLng,minLat,maxLng,maxLat เพื่อกรอง feature ที่ตัดกับกรอบแผนที่ได้

Example
GET /api/features/dma_boundary/5521040?bbox=98.9,18.7,99.1,18.9
GET /api/features/:shape/:pwaCode/:id

ดึง feature รายตัวด้วย Mongo ObjectId; ไม่พบคืน 404

Example
GET /api/features/step_test/5521040/{{step_test_id}}
PUT /api/features/:shape/:pwaCode/:id

แก้ไข geometry/properties ของ feature เดิม โดย validate topology ใหม่และไม่นับ feature ตัวเองตอนตรวจ overlap. สำเร็จจะ update MongoDB และ upsert mirror; ไม่พบคืน 404, topology ไม่ผ่านคืน 400

Request Body (step_test)
{
  "geometry": { "type": "Polygon", "coordinates": [[[98.98496, 18.76562], [98.98520, 18.76562], [98.98520, 18.76590], [98.98496, 18.76590], [98.98496, 18.76562]]] },
  "properties": { "STEP_ID": 1, "stepNo": "ST-01", "remark": "แก้ไขแล้ว", "pwaCode": "5521040" }
}
DELETE /api/features/:shape/:pwaCode/:id

ลบ feature จาก MongoDB และลบ row mirror ใน dmama_layer.<shape>; ไม่พบคืน 404

Example
DELETE /api/features/step_test/5521040/{{step_test_id}}
POST /api/features/:shape/:pwaCode/sync

ไม่มี request body. ใช้ backfill/upsert mirror dmama_layer.<shape> จากข้อมูล MongoDB ของสาขานั้น เหมาะสำหรับเรียกหลัง import ข้อมูลเดิมหรือซ่อม mirror ที่ขาด/ไม่ตรง. Endpoint นี้ไม่ใช่การสร้าง feature ใหม่ และไม่ใช่ full purge/reconcile row เก่าที่ไม่มีใน Mongo

Example
POST /api/features/step_test/5521040/sync
Response
{ "success": true, "data": { "synced": 42 } }
